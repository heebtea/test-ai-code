## 已可操作：AI 分享

在這個開發版本開啟「分享資料給 AI」：

1. 所選單日、任意開始／結束日、最近七天（台灣今天往前六天）、當月。
2. 勾選睡眠、各飲品、餐點、花費、活動、日照。事件和私人日誌預設關閉。
3. 備註、原始來源自由文字、心情等預設移除；若確實需要，另勾「包含備註、原始來源文字及私人內容」。事件／日誌若只選類別，敏感文字仍不會自動帶出。
4. 閱讀完整 JSON 預覽，再複製、下載 JSON 或系統分享。三種途徑使用同一份預覽快照與產生時間。
5. 在 ChatGPT 貼上／附上檔案，才算把該次快照交給 AI。

快照包含來源模式、產生時間、台灣時區、日期區間、資料版本、原始 ID、狀態及原有修改時間。欄位使用白名單，新增未知欄位不會自動外傳。食物／飲品名稱仍可能辨識個人生活，分享前必須看預覽。照片、模板、OCR 草稿不會出現在 AI 快照。

`records` 按紀錄日期；`transactions` 按付款／購買日期，是同一 ID 的帳務投影，不是另一筆支出，不得把兩邊金額相加。這可保留「今天付款、明天吃」及「以前購買、今天飲用」的差異。未知金額保留 null；未勾花費時，餐點／飲品中的金額與付款欄位也會排除。兌換咖啡不新增券面支出。

### 私人 Drive 手動路徑

下載所選區間快照 → 存入自己 Drive 的「限制存取」資料夾（勿開啟任何知道連結者）→ 使用 ChatGPT 已授權的 Drive 連接器選擇／讀取該檔；若該連接器不支援讀取原始 JSON，將同一檔案附加到對話，或直接貼上快照。

這條路徑需使用者主動存檔；不是自動同步、不保證連接器立即索引、不保證任意帳戶的連接器支援 JSON。日期檔名與 generatedAt 用來核對版本。未實際上傳任何使用者檔案，也未驗證本帳戶連接器讀取。已分享出去的副本不能遠端收回。

## 私人同步選型

官方文件查核日期：2026-11-01。以下成本／維護評估為本專案判斷，免費額度仍以服務後台當時顯示為準。

|方案|免費／成本|開發及維護|私隱與 iPhone|未來 AI 查詢|
|---|---|---|---|---|
|Google Drive 私人檔案|Drive 標準 API 不另收費；使用自己帳戶儲存配額|單檔手動備份最簡單；自動同步仍須 OAuth、檔案版本競爭、離線佇列及衝突處理|系統分享方便；appDataFolder 只有建立它的 app 可讀，其他 Drive app 看不到|普通私人檔案可嘗試既有連接器；隱藏 appDataFolder 不是 ChatGPT 通用入口；日期／類別查詢需額外處理|
|**Supabase Auth + Postgres（選擇）**|Free：500 MB DB、50,000 MAU、5 GB egress；閒置一週可能暫停，免費無自動 DB 備份|帳戶、資料庫與原子版本交易同平台；不需自行維護 OAuth 登入服務即可完成 app 的登入；另有 SQL 權限與備份責任|靜態網頁可呼叫帶驗證的 API；本版 Email OTP、Token 只留記憶體；每次重開要登入|適合逐日／分類查詢，但仍需獨立 OAuth 唯讀 gateway/MCP，不能把同步權限直接交 AI|

選 Supabase 是因為逐筆 CAS、身份隔離和未來有範圍的查詢比整檔同步更符合需求。現階段最省事的可用路徑仍是手動快照／完整備份；使用者尚未決定或授權雲端服務時，持續本機模式。

## 同步實作範圍

- `src/private-sync.js`：三方比較（本機、基底、雲端）、以 ID 更新、revision 比對、持久待送狀態、可重試 CAS、tombstone、雙方衝突保留、明確選擇版本、帳戶／專案綁定。
- `src/supabase-sync.js`：實際 REST adapter，OTP、驗證、登出、list/CAS RPC；未用真帳戶連線。僅接受 HTTPS `*.supabase.co` 專案與 `sb_publishable_` 公開金鑰；不接受 service_role／secret。
- `supabase/private-sync.sql`：可在**新的、經使用者授權的專案**執行。資料表啟用 RLS 並撤銷直接表存取；只有限定 authenticated RPC 可用，security-definer 函式固定 search_path、逐次核對 auth.uid 與允許帳戶並限制 owner。AI OAuth client_id 被拒絕。
- `src/private-sync-ui.js`：明確同意後才登入並上傳全部結構化紀錄；顯示狀態、最後完整同步與衝突。可記住公開 URL/key，不保存 Email／驗證碼／Token。重開頁面預設不連線。同步期間仍可本機修改，過期回應不覆蓋新修改。
- 目前每輪取得完整的結構化遠端清單（最多 20,000 含刪除標記），不是增量拉取；長期大量資料需評估傳輸額度與後續分頁／游標設計。當頁面仍開著且已授權，編輯後排程同步，網路恢復會重試；失敗可按「立即同步／重試」。沒有背景 Service Worker，也不保證關閉頁面或離線重新載入後能開啟 app。
- 生活紀錄與 OCR 草稿同步；**照片、模板、設定不自動同步**，仍用完整備份。這不是整台裝置的完整鏡像。
- `second-brain-lite-v2` key 不變；旁存 `second-brain-sync-v1` 記錄基底、衝突、待送狀態，與 `second-brain-sync-commit` 寫入回復日誌。短本機交易與整輪同步分別使用 Web Locks。
- 上傳成功但回應丟失，可依持久待送狀態辨認；重試不增加重複資料。刪除保留 tombstone，不自行清除歷史。雲端遺失版本、版本倒退、同版本異內容會停下。
- 本機寫入失敗時回復；若回復也失敗，留下日誌並禁止再寫入，重新開啟後保守回復。若發現與回復日誌不相符的第三個版本，停止並要求人工處理，不猜測覆蓋。
- 日期日曆統一 `Asia/Taipei`；舊資料既有 date/time 字串不重算，原本無修改時間的舊紀錄不補造。同步 revision／server_updated_at 在外層，不混進攝取、帳務與小誌統計。

### 安全邊界與備份

同步預設關閉；開啟會上傳私人日誌／草稿，介面明示，不把「AI 預設不分享」誤認成「私人雲端不儲存」。本版本使用 HTTPS 與服務端授權隔離，**沒有端到端加密**；專案擁有人／服務方的管理能力不等於零。公開 Pages 只有程式，不包含生活紀錄。

停止同步會清除記憶體授權並阻止回傳套用；已經送到伺服器的請求可能已完成。登出撤銷工作階段，但已簽發 JWT 到期前仍可能有效。需要立即拒絕存取時，移除 `sbl_allowed_users` 的使用者；每次 RPC 都重新查核。

同步不是備份。升級、啟用同步及解衝突前先下載完整備份。完整備份繼續含照片／模板，不含 Token／同步身份。另有「匯出同步狀態與紀錄」保留基底、衝突、tombstone 及待送資料；此檔是私密故障回復證據，**不提供自動匯入**，不可用一般匯入器混入。

本版不提供切換到另一帳戶後自動搬資料的功能；帳戶不同會拒絕上傳。無 tombstone 自動壓縮／永久清除。大規模資料、磁碟永久損壞與被清除的瀏覽器儲存不在已測保證內。

開發版本 CSP 的 connect-src 新增 `https://*.supabase.co`，以支援使用者自己指定專案；程式另限制 URL 形狀、禁止轉址、omit cookies。script-src 仍 self。正式網站尚未套用任何此類變更。

## ChatGPT 讀取：明確結論

**尚未直接連接。** 現在可用的是手動安全快照；有可測試的同步實作與唯讀 handler，沒有完整 OAuth 發證端、實際 MCP 註冊或真實雲端資料來源。

`server/ai-read.js` 是可測的 GET `/records?from=YYYY-MM-DD&to=YYYY-MM-DD&types=water,meal` handler。只接受已驗證 grant 的 owner、期限、日期區間與類別；不接受 query 指定 owner；每次重新查核撤銷；拒絕非 GET，回應 no-store；最長 31 日，可分批彙整月報；預設排除敏感內容。測試中的 verifier／資料層是合成替身，**不代表已實作 JWT 簽章驗證或 OAuth**。

後續實際接法：

1. 在使用者授權的後端建 OAuth 2.1 / PKCE 流程、授權同意頁、issuer/JWKS、resource audience、過期／撤銷的伺服器 grant 儲存；scope 只給 `records:read`。
2. 提供 MCP protected-resource metadata 與 OAuth discovery，依當時 ChatGPT 支援方式註冊 client（CIMD、DCR 或預註冊）。不能以一條永久 token URL 代替 OAuth。
3. MCP 只暴露 `get_records(from,to,types)` 並標記 readOnlyHint；**伺服器本身也要禁止修改**。不能只靠 readOnlyHint。
4. 將 handler 的 verifyGrant 接到真正簽章／issuer／audience／scope／expiry／即時撤銷驗證，owner 由 grant 取得。readRows 只查 owner，依日期與類別篩選；選 spending 時，必須查 record.date 與各種 purchaseDate/paymentDate 的付款軸，不能只查 record.date。
5. AI 使用獨立資料庫唯讀角色／函式，不可拿 app 的可寫 JWT 或 service_role 給 ChatGPT。舊／新 token、跨使用者、超出日期及分類範圍測試都必須在部署服務補驗。
6. 使用者在 ChatGPT 安裝／加入相容 app，走 OAuth 授權，再用合成紀錄問「查看我 11 月 1 日的 Second Brain Lite 紀錄」。對比已同步版本、產生時間、撤權後 401，全部通過才可稱已連接。

官方產品支援與帳戶可用性須以當時介面為準；建立 REST API 本身不等於 ChatGPT 能呼叫它。

## 必須由使用者設定／授權

現在不需要授權我再開發分支；外部服務部分需以下操作：

1. 先審查 Draft PR，不合併、不部署。取得開發版本後以自己的測試環境驗證。
2. 若採用 Supabase：自行建立 Free 新專案、確認區域／資料政策；不要啟用付費方案。執行此分支 SQL；建立自己的 Auth user、停用公開註冊，將該 UUID 加入允許清單。
3. 設定 OTP 郵件模板使用 `{{ .Token }}`，確認郵件寄送限制及收信；若內建寄信不適用，SMTP 需另外明確設定，本次不代建立付費寄信服務。設定合理 JWT 到期時間。
4. 在兩台裝置的開發版貼上專案 URL 與 publishable key，先用合成資料測登入、同步、離線、衝突與撤銷，再決定是否使用真資料。
5. 實體 iPhone Safari 驗收複製、檔案下載、系統分享、長內容捲動、離線已開頁面及重新登入；確認照片仍走完整備份。
6. 如要 ChatGPT 自動讀取，另行授權建置唯讀 OAuth/MCP 後端並完成上面的連接驗收。這一步尚未完成，不能只靠填一個 API URL。
