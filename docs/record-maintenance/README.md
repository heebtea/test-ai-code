# JSON 補正匯入與當日紀錄管理

以 `main` 的 `269f0a7` 為基準。#19 與 #20 的統計、#22 的資料橋接與私人同步，以及 #23 的三欄小誌均已在基準內。#24 的回歸修補仍是獨立 PR，本次分支由 `main` 建立。

## 操作

1. 從首頁選「匯入 JSON／補正」。匯入檔需是 v2–v8 紀錄 JSON。
2. 核對新增、更新、完全相同、衝突、略過與驗證失敗件數。可選「保留現有紀錄」、「採用匯入的補正紀錄」或「逐筆比較後決定」。更新與略過可能同時列在衝突總數內。資料驗證失敗的各筆會列明原因並排除。
3. 逐筆展開可比較日期、起訖時間、容量、金額、付款與攝取狀態、份量、來源及修改或補正時間。匯入檔省略的選填欄位會保留現有值，明確的 `null` 仍表示未知。選好才按「確認匯入」。
4. 整日重建時，先選日期並展開「當日紀錄管理」。選「刪除當日全部紀錄」，核對總筆數及分類，按「繼續並建立備份」。需要跨裝置保存時先「下載當日備份」，再按有日期的確認按鈕。
5. 誤刪可選「復原上次當日刪除」。若要從檔案救回或以另一份 JSON 重建，使用「還原完整／舊版備份」，選當日備份或只含目標日期的紀錄 JSON，再核對預覽。一般補正入口會略過已知已刪除的 ID。用一般舊版備份重建後，如有開啟私人同步，可在同步設定按「立即同步／重試」。

當日刪除依紀錄的 `date`。例如 11/26 的餐點紀錄付款日為 11/27，刪除 11/27 後，該餐點仍可出現在 11/27 的花費統計。刪除會涵蓋當日的十種正式紀錄及有相同日期的 OCR 草稿。此操作的日期、筆數與範圍與清除整部裝置的歷史資料不同。

## 根因與修正位置

| 檔案 | 修正 |

| `src/record-import.js`、`src/record-import-ui.js` | 舊首頁執行 `merge` 時，同 ID 只回報衝突。新流程以 ID 尋找現有紀錄，深度比對內容，逐筆驗證並讓使用者選擇版本。類別不同的同 ID、檔內重複 ID 與已知被刪除的 ID 無法由一般匯入覆蓋。 |

## 資料安全與同步

- 補正預覽唯讀。確認時會重查紀錄和已刪除狀態，先組成完整結果，再透過一次本機寫入提交。儲存配額不足或預覽過期時，保留當下的本機紀錄。驗證失敗的列會在預覽中明列，其餘有效列可在同次確認寫入。
- 本機撤銷保留各日期最近一次刪除的回復點。照片仍存在本機，回復紀錄後可重新連上同 ID。瀏覽器清除網站資料後，可用已下載的備份救回紀錄及其照片。備份檔含原文與照片，請私下保存。刪除前備份無法建立或超過 100 MB 時，應用程式會保留紀錄。
- 同步沿用既有版本及 CAS。未曾上傳的 ID 暫存在本機刪除意圖中，之後遇到該 ID 的遠端紀錄才有版本可標記。已同步的刪除以雲端 tombstone 保留。其他裝置在離線時仍可能暫時顯示舊副本；若有併發編輯，同步會留下待處理衝突。本機復原或明確的備份還原可以重新建立原 ID。
- 現有 v2–v8 檔案可讀。飲品「部分」狀態使用 v8，舊版程式的驗證器可能尚未支援這個新增狀態。批次刪除使用瀏覽器 Web Locks，與完整備份共用鎖。正式 Supabase、帳號及同步設定均未參與本次驗收。
